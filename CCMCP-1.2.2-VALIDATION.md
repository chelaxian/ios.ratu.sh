# CCMCP 1.2.2 — проверка 2026-10-22

Исправлен повторный отказ плитки MCP после 1.2.1. У стороннего процесса
CatMCP сохранялся TCP LISTEN на 0.0.0.0:9000, но очередь непринятых
подключений достигла 126–127 при лимите 128. Новые подключения истекали
по таймауту. Плитка считала службу выключенной и повторяла включение уже
работающего экземпляра вместо его остановки. Причина остановки обработки
соединений внутри стороннего сервера не установлена.

Теперь CCMCP читает состояние TCP-сокетов ядра через proc_pidinfo и
proc_pidfdinfo. Проверяются исполняемый файл CatMCP под активным /var/jb,
тип TCP, порт и состояние LISTEN. Проверка не подключается к серверу и
не заполняет его очередь. Один launcher, привязанный без listen сокет и
ошибка чтения не считаются работающим сервером. При недоступном чтении
помощник возвращает unknown; отображение последнего состояния сохраняется.
LISTEN означает запущенный сетевой сервер; это не гарантия обработки
произвольного HTTP-запроса. Даже зависший экземпляр можно выключить плиткой.

Также устранена зависимость пути настроек от getpwuid(501): в разных
контекстах запуска помощника iOS и Procursus home давали разные копии
com.catmcp.server.plist. После команды включения наблюдались enabled=true
в iOS home и enabled=false в Procursus home, запуск не подтверждался.
Команды синхронизируют только enabled в каноническом файле и существующей
отдельной копии Procursus. Остальные ключи каждой копии сохраняются.

## Проверено

- iPhone15,3, iOS 17.0 (21A329), Dopamine 3.0.12, ElleKit 1.2.
- macOS/Xcode CI 39804925497, исходники ce6de2d: сборка, подписи, rootless
  iphoneos-arm64 и arm64e PTRAUTH 0x80000002 прошли проверку.
- Тест macOS: bind без LISTEN, LISTEN, закрытый сокет, чужой порт/PID;
  1000 чтений не создают ни одного клиентского подключения.
- Установка итогового DEB поверх кандидата 1.2.2, права setuid-помощника.
- Пользователь подтвердил физическое OFF/ON после установки первого
  кандидата с тем же кодом плитки и пассивной проверкой сокетов.
- Итоговый кандидат: тапы 1/1/4/3/3/4 дают правильное последнее состояние,
  без ошибок действий. Одиночные OFF/ON около 0.33/1.28 с; быстрые серии
  около 0.47–1.55 с. Это измерения конкретного телефона, не гарантия времени.
- Внешние OFF/ON/OFF/ON через SSH: команды успешны, плитка отражает состояние
  без вызова обработчика тапа; итоговый MCP tools/list возвращает HTTP 200.
- Прямые команды с телефона: OFF ~0.28 с, ON ~1.23 с, чтение ~0.15 с.
- Итоговый кандидат: 200/200 пассивных чтений ON, медиана ~84 мс,
  максимум ~119 мс; тот же PID, очередь 0→0. Предыдущий кандидат с тем же
  кодом чтения: 500/500 ON, очередь 0→0.
- Хеши всех ключей настроек кроме enabled до/после совпадают в обеих копиях.
- SHA256 установленных модуля и помощника совпадают с итоговым DEB.
