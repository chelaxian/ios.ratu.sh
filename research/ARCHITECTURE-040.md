# MULTI VPN: решение и обязательные ворота безопасности

Это план интеграции подтверждённых частей эксперимента, не описание готового
режима. Продуктовый демон пока отклоняет MULTI. На телефоне остаётся 0.3.0.

## Разделение ответственности

1. Preferences хранит MATRIX: bundle ID → UUID сохранённой конфигурации.
   Неизвестный UUID никогда не означает DIRECT. Скрытые списки сохраняются.
2. Отдельный контроллер MULTI в root-демоне владеет только выбранными
   конфигурациями и своим NECP-сеансом. Однопрофильный supervisor в этом режиме
   не управляет VPN. Резервирование в MULTI не применяется.
3. Для PacketTunnel конфигурации используется штатный `NEVPNApp` с исходным
   протоколом и `tunnelType=1`, правилами приложений и исходным UUID конфигурации.
   Тип сеанса — 2. Нужен настоящий `loadFromPreferences` перед стартом.
   IPsec/Personal/AppProxy не следует объявлять поддержанными этим способом.
4. Штатные per-app политики выбирают профиль приложения и обслуживают DNS.
   Контрольные правила: реальная идентичность провайдера → DIRECT; выбранное
   приложение → DROP до готовности / SKIP к штатным правилам после готовности;
   остальные → DIRECT. Ручной IP_TUNNEL не используется: тесты не прошли.
5. Разделение выполняется NECP и отдельными utun/IP-адресами, не Linux netns.
   Интерфейс ищется по точному UUID протокола в SCDynamicStore, не по номеру utun.
6. Совместимость raw-fd движков требует обычного четырёхбайтового заголовка utun.
   Узкий прототип nesessionmanager снимает только флаг PROC_UUID при создании
   интерфейса конкретного принадлежащего эксперименту appVPN. Остальные socket
   options сохраняются. Вторая установка после connect считается успешным no-op
   только если getsockopt подтвердил фактически установленное требуемое значение.
   Системные VPN, MDM и чужие per-app конфигурации нельзя затрагивать.

## Перед интеграцией framing-модуля

- Вынести ownership в root-owned manifest с фиксированным путём, правами и
  строгой схемой UUID; пользовательские Preferences не являются таким manifest.
- Область вызова — точный UUID appVPN + текущий поток; вложенные вызовы должны
  восстанавливать предыдущую область, а не уничтожать её.
- Проверять класс, селекторы, ABI и XPC типы; при несовпадении отказываться от
  MULTI, а не включать глобальное изменение сокетов.
- Отдельный фильтр только nesessionmanager. Полный macOS arm64e PTRAUTH gate.
- Проверить PacketFlow-клиент (OpenVPN), другие выбранные провайдеры, IPv6, DNS,
  возвращение из сна и совместные профили одного приложения. Два raw-fd клиента
  не доказывают универсальную совместимость всех VPN-приложений.

## Транзакция и восстановление

До изменения сохранять оригиналы только на телефоне в root-owned каталоге 0700,
архивы 0600; никогда не сохранять их в Git/логи/публичный каталог профилей.
Сначала блокировать назначенные приложения и подготовить физические исключения
провайдеров, затем сохранять appVPN конфигурации и стартовать сеансы.
Готовность — статус Connected и точный интерфейс; это ещё не проверка интернета.

При смене MATRIX/режима, выключении, сбое и перезапуске демона восстанавливать
оригиналы в сериализованной транзакции. Не удалять архив/manifest до успешного
восстановления. Не перезаписывать оригинальную копию уже преобразованным appVPN.
Вновь появившиеся приложения заново получают UUID исполняемых файлов.
Удалённый профиль или отказавший назначенный VPN остаётся fail-closed.
Независимое переподключение не должно переключать другие рабочие VPN.

## Extra

Обычный supervisor остаётся только в BYPASS/TUNNEL ONLY. Redundancy включает
Health и Always ON, перебирает непроверенные резервы и останавливается после
неуспешного круга. Без резервов отдельный счётчик циклов ограничивает повторные
восстановления без единого успешного Health Check. Счётчики и отмена устаревших
асинхронных запусков должны проходить отдельную интеграционную проверку.

Защита музыки/PiP выключена по умолчанию и видна только при включённом LS.
Источник воспроизведения — MediaRemote. Источник UI-блокировки — read-only мост
из SpringBoard; системное lockstate оставлено резервным источником. При паузе
возобновляется задержка LS, неизвестное состояние сохраняет VPN. Новые проверки
не должны выполняться постоянно, когда зависимые опции выключены.

## Не выпускать до

- Повторяемого одновременного выхода двух приложений с разными публичными IP.
- Полной транзакции crash recovery и fail-closed проверки отказа одного профиля.
- Проверки сна/разблокировки, паузы музыки и PiP на установленной сборке.
- Проверки rollback на исходный 0.3.0 и подписанного macOS-артефакта.

APT, main и боевой сайт остаются 0.3.0; экспериментальная ветка не публикует релизы.
