# App Split VPN — архитектура и передача разработки

Дата: 2026-09-28. Состояние: пакет 0.1.0 собран в GitHub Actions и установлен на тестовый iPhone; пользователь разрешил продолжать после первоначальной просьбы остановиться перед сборкой.

## Требование

Один универсальный механизм для активного системного VPN, независимо от приложения и протокола. Два сохранённых списка приложений с поиском и переключателями: VPN и DIRECT. Режимы TUNNEL ONLY и BYPASS. Настройки RU/EN. Публикация в chelaxian/ios.ratu.sh после проверки.

## Принятое решение

Отдельный root LaunchDaemon владеет собственной сессией NECP. PreferenceLoader + AltList задают настройки. Инъекции в приложения, SpringBoard и nesessionmanager в конечном продукте не нужны. Frida использовалась только для кратковременного исследования.

Слой находится в системном выборе сетевого пути до передачи пакетов VPN-провайдеру. Он не реализует VPN-протокол, не читает полезную нагрузку, не меняет профиль VPN, его учётные данные или конфигурацию сервера.

| Режим | Условие в своей NECP-сессии | Результат |
|---|---|---|
| BYPASS | effectiveApplication UUID принадлежит DIRECT | scopeToDirectInterface |
| BYPASS | остальные соединения | обычные системные правила VPN |
| TUNNEL ONLY | effectiveApplication UUID принадлежит VPN | skipWithOrder:0 — пропустить только свою сессию, затем обычные системные правила VPN |
| TUNNEL ONLY | остальные соединения | scopeToDirectInterface |
| Выключен / VPN отсутствует | никаких правил твика | обычная маршрутизация iOS |

Priority=control (число 1). В каждом условии обязательно allInterfaces. Без него в живом тесте curl оставался в VPN, хотя addPolicy/apply возвращали успех. VPN-исключения имеют order=100, общее DIRECT правило order=1000.

Использовать именно effectiveApplication, не PID и не realApplication: эффективный владелец позволяет системе относить делегированные соединения к приложению. Проверка WebKit и фоновых загрузок остаётся отдельным приёмочным тестом.

Общий статус: ne_session_manager_has_active_sessions из libsystem_networkextension. На телефоне вернул 0 без пользовательского VPN, несмотря на существование Apple ipsec/utun, затем пользователь включил CT. Нельзя определять VPN по наличию любого utun/ipsec: их было много даже до подключения CT. Опрашивать статус раз в секунду; UUID приложений пересчитывать раз в минуту и при изменении настроек. Соединения, созданные в коротком окне переключения, могут потребовать переоткрытия приложения. Это не kill switch.

## Граница универсальности

Никаких коннекторов CT/WireGuard/OpenVPN/IKEv2 и никаких жёстко заданных utun4/en0. DIRECT использует системный выбор физического пути, включая Wi-Fi/LTE. VPN-ветка сохраняет правила активного провайдера.

Следствие: если сам VPN настроен на исключение назначения, локальной сети или определённых приложений, твик не превращает такой профиль в полный VPN. Управляемый per-app App Proxy, PAC/HTTP-прокси, MDM Always On, несколько одновременно действующих политик и запрещающий обход includeAllNetworks требуют отдельной квалификации. Одного глобального булева статуса недостаточно, чтобы доказать, что для каждого назначения существует доступный общий IP-туннель. Не обещать «абсолютно любой VPN без исключений».

Не добавлять эвристику «самый большой номер utun», принудительную привязку всех приложений к en0 или изменения чужих профилей ради обхода этих ограничений. Если понадобится строго направлять выбранные назначения вопреки split-настройкам провайдера, это отдельный механизм и расширение приёмочной матрицы, а не косметическая правка.

## Владение и восстановление

- Своя NECP-сессия, никаких глобальных delete-all, изменения чужих NECP-сессий или прямого редактирования networkextension.plist.
- Все действия последовательно на main queue. Сначала подготовить новую сессию, затем apply, снять старую. Это НЕ атомарная транзакция между двумя сессиями; возможно короткое перекрытие.
- При ошибке подготовки сохраняется предыдущая рабочая сессия; UI показывает ошибку обновления. При исключении безопасно закрывается собственная сессия.
- При выключении, SIGTERM, удалении пакета правила удаляются; при смерти процесса владение сокетом должно снять их ядром — обязательно проверить SIGKILL на готовой службе.
- Нет сохранения NECP-правил в системный VPN-профиль. После перезагрузки без jailbreak твик не действует.
- Списки хранятся независимо. Пустой VPN в TUNNEL ONLY означает весь трафик DIRECT; пустой DIRECT в BYPASS означает штатный VPN.
- Идентичности main executable и расширений берутся из NEProcessInfo/LaunchServices; при ошибке разрешения установленного приложения новая политика не публикуется.

## Улики с устройства

iPhone15,3; iOS 17.0 (21A329); Dopamine 3.0.10; iphoneos-arm64; ElleKit 1.2; AltList 1.0.11.

1. Подтверждены селекторы NEPolicySession / NEPolicyCondition / NEPolicyResult на живом iOS.
2. До включения VPN curl показывал прямой адрес. Пользователь затем включил CT.
3. При CT без правил curl и wget показывали VPN-адрес.
4. DIRECT только для curl: curl показал прямой адрес при продолжающемся VPN.
5. TUNNEL ONLY с curl в VPN: curl показал VPN-адрес, wget одновременно — прямой адрес.
6. После удаления тестовых правил curl снова показал VPN-адрес.
7. Safari: copyUUIDsForBundleID вернул четыре UUID, а LaunchServices — три расширения; дополнительно предусмотрено объединение UUID расширений.

Это доказательство IPv4 HTTPS-маршрутизации для двух исполняемых файлов, а НЕ доказательство поведения всех приложений, DNS, IPv6, QUIC, LTE или других VPN-клиентов.

## Подпись и инструменты

Диагностическая macOS-сборка была запущена ДО просьбы остановиться перед CI: run 36448293601 (success). Первый run 36448260123 упал из-за sparse-checkout: в первый коммит попал workflow без research-исходников. Это исправлено следующим коммитом.

Новые CLI с ldid -S, CodeDirectory flags=0 завершались SIGKILL/137 даже после добавления CDHash. В dmesg: AMFI no CMS blob / Unrecoverable CT signature issue. Решение, проверенное на этом устройстве: явный ldid -Cadhoc -S<entitlements>, затем доверие конечному CDHash при необходимости. После этого самостоятельный arm64 probe запустился, разрешил UUID curl и apply вернул 1. Не переносить флаговую проблему на архитектуру NECP; не копировать bootstrap entitlements.

Служба — arm64. PreferenceLoader bundle — arm64 + современный arm64e; для последнего обязателен macOS/Xcode и проверка subtype 02000080. WSL-выход не устанавливать в Settings.

## Сборка и приёмка пакета 0.1.0

Workflow Build App Split VPN, run 36452308830, успешно собрал rootless DEB и иконку из коммита 9ba9cdc. Архитектура пакета iphoneos-arm64, Preferences bundle содержит arm64 и arm64e с subtype 02000080, оба исполняемых файла подписаны adhoc. SHA256SUMS проверен после скачивания артефактов.

На iPhone пакет установлен, служба запускается, панель Settings и оба списка открываются. При активном CT режим BYPASS направил Safari к 1.1.1.1 по en0 без пакетов на utun4, тогда как CLI остался в VPN. В TUNNEL ONLY Safari пошёл по utun4 без пакетов на en0, а CLI получил прямой внешний IP. После SIGKILL служба перезапустилась и восстановила четыре правила; после удаления тестовых настроек состояние стало disabled/rules=0 и CLI вновь использовал IP VPN. Тестовые настройки удалены.

Это подтверждает IPv4 TCP-маршрутизацию на данном устройстве, но не DNS, IPv6, UDP/QUIC, LTE, фоновые запросы или иной VPN-клиент. Пакет следует считать тестовым до их проверки.

## Исторический план после смены модели

1. Прочитать этот файл и HANDOFF.md. Проверить ветку feature/app-split-vpn и git status.
2. Запустить ручной workflow на точном проверенном коммите ветки. Проверить Swift-генератор, обе архитектуры prefs, rootless payload, entitlement/adhoc flags, dependency closure и SHA256.
3. До установки уточнить наличие пакета и предыдущей версии; в этой сессии сам твик НЕ устанавливался. Инсталлировать только проверенный macOS артефакт. Нужен корректный trust для конечных бинарников, если стандартная установка Dopamine его не обеспечит; не очищать общий trustcache.
4. Проверить запуск службы, настройки и два AltList. Селектор PSSpecifier setValues:titles: известен из AirKeeper, но на живом Settings в этой сессии не проверен: попытка Frida attach к приостановленному Preferences не удалась. Runtime guard не даст вызвать отсутствующий метод; если выбор режима недоступен, заменить его собственным UIKit-контроллером или проверенным API.
5. Выполнить матрицу ниже. Не публиковать пакет как готовый до приёмки.
6. Опубликовать DEB, иконку и исходники в main ios.ratu.sh; обновить индексы скриптом репозитория, проверить опубликованный SHA и Packages. Скопировать DEB на рабочий стол.

## Обязательная приёмка

- BYPASS и TUNNEL ONLY: два реальных приложения одновременно, видимый внешний IP по обе стороны; затем поменять списки местами.
- Приложение с WKWebView/Safari, фоновый NSURLSession, TCP и UDP/QUIC. DNS должен соответствовать выбранному пути; это ещё не доказано.
- IPv4 и IPv6; если сеть не даёт IPv6, явно оставить NOT TESTED, не заявлять отсутствие утечек.
- Wi-Fi/LTE, переподключение, отключение VPN, смена VPN-клиента хотя бы на второй независимый провайдер, отсутствие привязки к CT.
- Пустые списки, пересечение списков, оба языка, поиск AltList, сохранение после перезапуска Settings.
- Обновление/удаление выбранного приложения, восстановление UUID, ошибка разрешения не должна незаметно отправлять VPN-приложение напрямую.
- SIGTERM/SIGKILL/удаление пакета: правила уходят, штатный VPN работает; UI не показывает устаревшее «активен».
- includeAllNetworks/ограниченный per-app VPN: не выдавать непроверенную конфигурацию за поддержанную. Проверить и документировать фактические ограничения.
